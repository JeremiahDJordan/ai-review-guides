Which Apache SAI fixes main-5.0 was missing, and what restores them

This audit checked every Apache cassandra-5.0 and trunk SAI commit by behaviour against DataStax's 5.0 line (branch main, called main-5.0 here), restored the ones that apply in a 107-commit series on top of mainline, and filed the bugs it found.

Issue and PR numbers refer to the public fork JeremiahDJordan/cassandra; commits that are only on Apache's branches link to apache/cassandra.

Maintainer decisions that shape the classification

  • Deferred until DataStax moves to a 6.0-based branch: BETWEEN (19604, 19688, 19878, and 20154 with them) and 18492.
  • Strict filtering: replica filtering defaults to strict. 19018's relaxed semantics are restored behind an opt-in switch.
  • 18490 is restored with its default ON.
  • 21863: series 093 evaluates CONTAINS, CONTAINS KEY and their negations on unindexed frozen collections per element during SAI post-filtering; Apache rejects that case.
  • The virtual table is registered under Apache's name, sai_sstable_index_segments.
  • Filtered IN: a null element of a filtered single-column IN is ignored, as in Apache 5.0. Series commit 052 reverses that part of mainline commit eecce01e0fe.
  • Kept as documented deviations:
    • 18730, the vector dimension guardrail default;
    • 20334, prioritize_over_legacy_index defaulting to true;
    • 18782: case_sensitive, normalize and ascii are accepted on primary key columns, have no effect there, and warn for non-default values;
    • 21515, a full rebuild of one index rewriting the shared per-SSTable components (the DataStax repair and upgrade path).

Remaining read cost

Fix 01 brings range reads from SSTables back to main-5.0's speed. Memtable reads stay slower than on main-5.0 (5141da547d7), by 6% to 128% (40-column skip-list tables the most), and reads with an SSTable holding expired data by 23% to 94%. That is the cost of the correctness fix itself (8b535907ba1): a row kept alive by cells older than its expired row marker must not be dropped. Memtable-only reads against the code before fix 01 are within noise. On the Apache side (#158), memtable-only reads are still 77–141% slower.

Glossary

mainline
main-5.0-fb7f1b7aee-merge: the merge of Apache cassandra-5.0 fb7f1b7aee into main-5.0 5141da547d7, plus numbered CNDB-XXX commits. Published on the fork as in-progress/main-5.0-fb7f1b7aee-merge.
the series
The commits on mainline that restore Apache's SAI fixes and fix DataStax SAI bugs found in the same code, numbered 001 to 106 with 025b in the series table.
fail-before
A run of a commit's tests with the earlier production code, where they fail; they pass with the fix.
SAI sweep
All SAI unit test classes and SAI in-JVM dtests, at the default on-disk version or at ga.
strict / non-strict filtering
Replica-side SAI intersection semantics. Non-strict is the CASSANDRA-19018 behaviour, signalled per read by the ds.sai.nonstrict custom parameter; strict is the default.
RFP / SRP
Replica filtering protection / short read protection.
aa / ec / ed / ga
SAI on-disk versions: DataStax aa (DSE 6.8) and Apache 5.0 aa (read-only here), DataStax ec (written by default), ed, and ga (the latest); ba to fb are the DataStax versions in between.
DataStax messaging versions
DS 10 (100, Converged Cassandra 4.0), DS 20 (110, 5.0) and DS 21 (111), added by series 027 for LIKE semantics and blob indexes.
key 920 flake
