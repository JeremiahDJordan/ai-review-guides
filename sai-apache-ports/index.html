Review guide: Apache SAI fixes restored on DataStax main-5.0

This guide is for reviewers, human or AI, of the commits that bring Apache Cassandra's Storage-Attached Index (SAI) fixes into DataStax's Cassandra 5.0 line. It says what the commits are, where to start, what each group of commits changes, and what to check in each. The audit report has the full classification of every Apache SAI commit, the test evidence and the bugs filed along the way.

The change under review

  • Branch: main-5.0-fb7f1b7aee-merge (mainline in this guide): DataStax's 5.0 line (main-5.0, branch main of datastax/cassandra) merged with Apache cassandra-5.0 at fb7f1b7aee. The branch isn't published, so the commit IDs below can't be opened on GitHub; reviewers need access to the branch, and this guide doesn't publish the code. Its history has been rewritten before; if an ID doesn't resolve, find the commit by its subject.
  • Commits: 106 commits, git log --reverse fa5d580418e..ae493d880df, plus 1d5c08a0ffb (return only the selected static columns from a trie memtable partition read with no slice), which landed earlier. Every commit is CNDB-XXX: <summary>, by Jeremiah Jordan except the CNDB-19682 cherry-pick (572931a4f9b, by its original author).
  • Size: about 64,000 added lines, three quarters of them tests. The biggest commits are the reader of Apache-written SAI files (5e60c1c499a, +8,941), non-strict replica filtering (017d9e35c59, +5,834) and the static-row and row numbering fix (925eff0c75d, +4,124).
  • State: the series passed a private test runner on JDK 11 with 0 failures (see Evidence).

Background in four points

  1. DataStax built SAI for DSE 6.8 and contributed it to Apache as CEP-7. Apache Cassandra 5.0 then shipped its own implementation with its own on-disk format, also called aa.
  2. DataStax's tree has carried its own SAI since 2021 (STAR-121); on the 5.0 line that commit replaces Apache's SAI. Each later Apache SAI fix reached DataStax only by a hand port, and most never got one.
  3. The audit checked all 220 Apache cassandra-5.0 and trunk SAI commits against DataStax main-5.0 by behaviour: 34 are restored by these commits, 120 were already present or equivalent, 57 don't apply, 4 are kept as documented deviations and 5 are deferred.
  4. Many commits fix DataStax-only bugs in the same code. The restored fixes and their tests depend on them.

How to read a commit

  • The message is the specification. Each message says what was wrong, why, and what changed, with a reproducer in plain CQL where there is one. Check the code against the message, then the message against the code: a behaviour the code changes that the message doesn't mention is a finding.
  • Provenance lines at the end of a message name the upstream source: Adapted from CASSANDRA-NNNNN (apache/cassandra commit <sha>). for ported code, Tests adopted from CASSANDRA-NNNNN (...) for ported tests, and (cherry picked from commit <sha>) for an unchanged pick. Compare an adapted commit with its Apache commit: the differences should be what this SAI's code needs, not a different fix.
  • One complete fix per commit. Each commit builds, passes its own tests, and doesn't need a later commit to be correct. A later commit that changes an earlier one's code says so in its message.
  • NEWS.txt gets an entry for every change an operator can see: new settings, changed results, upgrade steps. Check that the entry exists and that it matches the code.

1. Mixed clusters with Apache Cassandra 5.0 nodes

59001b61e92, 331dd77ba02, 744cd7cf376, 017d9e35c59 (with c527cfcaffb, CASSANDRA-20189), a23830ebd5d (CASSANDRA-21700), 817347ca894.

A DataStax 5.0 cluster can contain Apache Cassandra 5.0 nodes during a migration. Apache Cassandra 5.0 nodes are on messaging version 13; DataStax nodes are on DS 10 (100) or later. These commits decide what a DataStax node sends to them and what it refuses.

A query whose filter has parts that only DataStax nodes can read (59001b61e92):

flowchart TD
    Q["SELECT with a row filter"] --> E{"empty filter?"}
    E -->|"yes"| S["sent as is"]
    E -->|"no"| R["nodes the query can contact:<br/>LOCAL_ONE, LOCAL_QUORUM, LOCAL_SERIAL: this datacenter's;<br/>other levels: every node of the keyspace"]
    R --> V{"any below messaging version DS 10,<br/>or live with a version not known yet?"}
    V -->|"no"| S
    V -->|"yes"| F{"DataStax-only parts?"}
    F -->|"no"| S
    F -->|"':' that '=' also serves on that column"| T["sent as '='"]
    F -->|"NOT IN"| T2["sent as '!='"]
    F -->|"OR, NOT CONTAINS, NOT LIKE, BM25, other ':' ..."| X["InvalidRequestException"]

The result of the node check is cached per keyspace and scope until a messaging version, gossip state, liveness, peer, token metadata or keyspace replication changes. A node not counted yet is still protected: the serializers refuse these parts for a node below DS 10, and the request fails at once. LIKE has its own check, at DS 21 (331dd77ba02).

Non-strict replica filtering (017d9e35c59), for a row whose restricted columns were written to different replicas:

sequenceDiagram
    participant C as Coordinator
    participant R as Replicas of this release
    C->>C: build the row filter once per read: relaxable if<br/>non_strict_replica_filtering_enabled, or a node below DS 10 can be contacted
    C->>R: read, with the ds.sai.nonstrict parameter only if relaxable
    R->>R: repaired data: intersect the index matches<br/>unrepaired data: union of each expression's matches
    R-->>C: candidate rows
    C->>C: reconcile the responses, then apply the filter<br/>(replica filtering protection)
    Note over C,R: Without the parameter, replicas filter strictly, as before.<br/>The data and digest requests, retries, protection reads and read repair of a read all use the same decision.

Ordered queries, ONE and LOCAL_ONE, single-replica keyspaces and filters on one mutable column stay strict. A strict filter is never sent to a node below DS 10, which would relax it: the serializer refuses it, and the coordinator reads the query or page once more with a filter that replicas can relax.

Check:

  • Decisions about what to send use the messaging version only, never a release version. A peer below DS 10 is an Apache Cassandra node (or a DataStax node pinned to Apache's version).
  • Node and peer metadata comes from org.apache.cassandra.nodes, which DataStax deployments can replace with their own implementation.
  • A refused query gets an InvalidRequestException that says why, not a wrong result from the Apache node.
  • The read after a refused strict filter happens once, with new selectors, and doesn't repeat warnings.
  • Tests: the in-JVM dtests of these commits (DataStaxOnlyRowFilterDistributedTest, LikeAcrossDatacentersTest, BlobIndexDistributedTest) cover peers on older messaging versions.

2. On-disk formats

3. Index lifecycle: builds, restarts, imports and streams

60cfffb636a, 039862defa6 (CASSANDRA-20732), 904759d3a01, 995d2963296, c8e58e04874, 7ca866b71d4, af4e52a0c11, 2cb2f35aefb, e8a4b150529, 1ae87c2c71a, 041930d6280, ececdb3a126, 4f5df98f6e3, 1ea565c5b31 (CASSANDRA-21671), ae493d880df, 5ac6f62ee4f (CASSANDRA-19987), ac17666cdb8 (writer abort logging, CASSANDRA-20695).

These decide when an index is queryable. The rule they all serve: an index is queryable only when every live SSTable has complete, correct components for it.

SSTables added by a stream or an import (c8e58e04874):

flowchart TD
    S["a stream or an import receives SSTables"] --> B["build on them only the indexes that are missing,<br/>incomplete or written with an obsolete encoding"]
    B -->|"stopped or failed"| F["the stream or import fails;<br/>the index stays queryable"]
    B -->|"built"| A["add the SSTables to the table"]

Check:

  • Every path that makes an index queryable (initial build, rebuild, restart, import, stream, truncate) checks the live SSTables, not a snapshot taken before the build.
  • A failed or stopped build leaves the index non-queryable, or fails only the stream or import, as the message says.
  • Ownership and locks: who may write or delete an SSTable's component files while another build runs, and that a dropped index's build can't change the state of a new index of the same name.
  • Races are tested by pausing threads at chosen calls with inject.Injections (Byteman). Check that each test asserts that its pause was reached: a pause on a call that no longer happens passes without testing anything.

4. Memtables and the write path

Trie memtables: 1d5c08a0ffb, 6aea1e383fa, fcb65f1ab87, 572931a4f9b and a6b52517ff5 (CNDB-19682), ce4eebbd4f1, d4a5fc7aa74 (CNDB-19681), ecd92655eec. Two writes racing on one partition of a skip-list memtable (0235c5d3984):

sequenceDiagram
    participant W1 as Write 1
    participant W2 as Write 2
    participant P as Partition
    participant I as SAI memtable index
    Note over W1,I: Before: index events for every merge attempt, before its CAS
    W1->>I: events of attempt 1 (removes the row's old values)
    W2->>P: merge and CAS: wins
    W1->>P: CAS of attempt 1 loses
    W1->>I: events of attempt 2
    W1->>P: CAS of attempt 2 wins
    Note over I: the events of the lost attempt removed values the row still holds
    Note over W1,I: After, on tables with SAI: merge and CAS under the partition's lock,<br/>events held per attempt, dropped for a lost attempt, delivered once the update is applied

Check:

  • An index event is delivered once per applied update, in apply order, and never for an update that wasn't applied.
  • An update that keeps a value in a row doesn't remove that value from the index; a deletion or expiry removes only what it shadows.
  • 0235c5d3984 takes a partition lock only for tables whose indexers ask for atomic updates; NEWS.txt gives the throughput cost with many writers on one partition.

5. Query semantics

Restored from Apache: 8faae9aa793 (equivalent of CASSANDRA-19177), 190070cc374 (20191), 91dd80addba (20243), e1406d1499a (20866), b6c0e11a1ab (term size guardrails, 19493 and 18926), a11b47ad8ac (19544), c0a1d0cba68 (19953), 214dc9b9b8d (part of 20313), 42e6e2ec137 (21525), 13731e74fd5 (non-float vectors, 18715). Same case as an Apache ticket, different behaviour: 8d9619fa249 (CASSANDRA-21863 rejects the query; this evaluates it per element). DataStax-only fixes: f723d246377 (equivalent of CASSANDRA-20258), cd3ce5321b2, fd61c6873d4, e70ba28bab2, d7b5dd2f369, f6d46514c01, 5c4ac0ce4c9, 11abb672196, 8defe3bc673, 4a72521b752, 27de9b32cb3, a5bb64889ef, 2f1db37a433, e62738daee6.

Check:

  • An SAI query returns the same rows as the same query with ALLOW FILTERING on a table without indexes. Tests compare with that table, from the memtable, from SSTables and after compaction.
  • Analyzed columns: :, =, CONTAINS and their negations each say which analyzer applies.
  • Negations (!=, NOT IN, NOT CONTAINS, NOT CONTAINS KEY) never subtract index matches that weren't checked against the row.

6. Static rows, OR, paging and replica filtering protection

925eff0c75d, 3c5bbbcc208, a8c4b2529ec, 8af41195ad5, 3f9e28fc617, 914fcd63296, d2fbec59d50, 6d42b5aea4c, 406eb1cceaf, bef8706e945, d00fa3410ea.

Partitions that have only a static row, and filters that mix static and regular columns, are where SAI, RowFilter, limits and the coordinator's reconciliation disagreed.

Check:

  • A replica returns a partition for its static row alone only when that row satisfies the filter on its own.
  • Limits, PER PARTITION LIMIT and paging count those partitions.
  • Replica filtering protection reads the whole partition from a replica whose static row is stricter than the merged one. Apache Cassandra 5.0 has the same gap; the message of d00fa3410ea gives the case.
  • What a replica holds while it waits to decide is bounded by the tombstone failure threshold.

7. ORDER BY and vector search

3e1c35ba143 (CASSANDRA-19661), 3d5f5d1e18e (tests from 20086), 40881baecc3, d2e480e4ca2, 50deef58ddf, d98b674b593, 6d56a449bca, be474291df8.

Check:

  • Each partition and row is returned at most once, and the limit counts rows, not keys.
  • With a vector in a primary key column, a dead row is never returned.
  • Vector recall tests check recall over many queries, not one; a single graph search can miss a reachable row.

8. Compaction and expiration

67f7c0f321a and e020bdb9709 (CASSANDRA-20829, compaction and UCS expiration tasks), af4e52a0c11.

Check that dropping a fully expired SSTable still tells the indexes about its rows, and that compaction doesn't read an SSTable it drops whole.

Decisions already made

A review should check that the code and the documentation agree with these, not reopen them:

  • Replica filtering stays strict by default. CASSANDRA-19018's relaxed filtering is restored behind sai_options.non_strict_replica_filtering_enabled (default false), because it can make queries much more expensive.
  • CASSANDRA-18490's checksum check on partial builds is on by default, as in Apache Cassandra.
  • A null element of a filtered single-column IN is ignored, as in Apache Cassandra 5.0. An earlier mainline commit rejected it.
  • CONTAINS on an unindexed frozen collection is evaluated per element; CASSANDRA-21863 rejects the query.
  • Documented deviations: CASSANDRA-18730 (the vector dimension guardrail default), CASSANDRA-20334 (prioritize_over_legacy_index defaults to true), CASSANDRA-18782 (unknown options accepted with a warning) and CASSANDRA-21515 (a full rebuild of one index rewrites the shared per-SSTable components).
  • Deferred to a 6.0-based line: BETWEEN (CASSANDRA-19604, 19688, 19878, 20154) and CASSANDRA-18492.
  • Read, not written: these commits read Apache's aa format through a read-only version; nothing in them writes it.

Checks that apply to every commit

  1. Tests fail without the fix. For a behaviour change, revert the production change and run the commit's new tests: at least one must fail. A test that passes either way tests nothing.
  2. Tests match their neighbours. New tests use the same base class and helpers as the tests next to them (SAITester/CQLTester, createTable, execute, assertRows, flush, compact), and in-JVM dtests use cluster.coordinator(n).execute.
  3. Comments are short and state facts. No comments that narrate the change or the bug's history.
  4. Internode behaviour depends on the messaging version only.
  5. No new cost on the read and write hot paths without a reason the message gives.
  6. Edge cases off the intended use are refused with a clear error or documented, not handled with extra mechanisms.

Using this guide with an AI reviewer

Give the reviewer one commit, or one area above, at a time, with:

  1. the commit (git show <sha>) and, for an adapted commit, the Apache commit from its provenance line;
  2. the "Check" list of its area and the checks that apply to every commit;
  3. the instruction to report each finding with a severity (blocker, should fix, nit), the file and line, a concrete failing case, and a suggested fix, and to say plainly when it found nothing.

Then triage: fix correctness, data loss and missing tests; decline style preferences and pre-existing issues outside the commit with a one-line reason, and file those separately if they are real bugs.
